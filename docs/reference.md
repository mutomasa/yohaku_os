## 1. 全体の骨格：知性サイクル

本書の中心は、次の5つを繰り返す**「知性サイクル」**である。

```text
知る → 考える → 決断する → 行動する → 修正する（フィードバック）
  ↑                                              │
  └──────────────────────────────────────────────┘
```

- 「知能」は情報を処理する性能、「知性」は**知識を行動に変え、現実を変える力**。知能ではAIに勝てないが、AIという道具を使いこなす知性は鍛えられる（03）。
- AIが出すのは平均的な**「最適解」**。自分で行動して確かめた答えが**「実践解」**。最適解を行動によって実践解に変えるのが知性（03）。
- 「知る・考える・決断する」は頭の中で完結するため、それだけでは現実は変わらない。現実を変えるのは「行動する」だけ（64）。

章立ては、このサイクルに「整える」と「AI時代にあえてすべきこと」を加えた構成になっている。

| 章 | テーマ | 撮影した項目 |
| --- | --- | --- |
| 1 | 「知性」とは何か | 03 |
| 2 | 知る：インプットの質と量を改善する | 11, 14, 17, 23 |
| 3 | 考える：本質的な思考力を鍛える | 29, 31, 33, 34, 35, 36 |
| 4 | 決断する：意思決定でスピードを上げる | 50, 54, 55, 56 |

| 8 | AI時代にあえてすべきこと：人間本来の力を磨く | 113 |

## 2. 項目ごとのエッセンス

各項目について、要点、本書の Action Plan、yohaku で使えそうな点をまとめる。

### 第2章 知る

#### 11 デザインする（全体最適化）
- AIや検索を使い始めると、目的を見失って脱線しやすい。生成AIのヘビーユーザーほど残業時間が長い傾向があるという調査もある。
- AIを使う前に全体像を設計する。手順は **①ゴール → ②全体像（現在地と次の一手） → ③判断基準 → ④制約（やらないこと・時間・締切） → ⑤問いの設定**。
- 1日の最初にTO DOリストを書くのも、仕事のデザインにあたる。
- Action Plan：目的・ゴール・問いを決めてから作業しよう。
- **yohaku**：朝のブリーフの冒頭に「今日のゴール／やらないこと／締切」を本人が書く欄を設ける。AIに作業させる前に、この5項目の入力を促す画面を出す。

#### 14 アンテナを立てる（選択的注意）
- 目的のないブラウジングは脳を疲れさせる。「今、何を調べるのか？」「なんのためにスマホを使うのか？」を先に決める。
- 「とりあえず集める」インプットではなく、**アウトプットを前提に、使う情報だけを集める**。使わない情報は要らない。
- Action Plan：ほしい情報のアンテナを立ててからスマホを開こう。
- **yohaku**：技術調査やRSSの収集を「今週のテーマ（アンテナ）」で絞り込む。テーマ外の情報はブリーフに出さない。

#### 17 確認する（クロスチェック）
- AIは嘘をつくし、よく間違える。SNS投稿、提案書、論文、数値データ、法務・医療に関わる文書は必ず確認する。
- 確認の方法は、①AI自身に根拠を聞く、②出典が実在するか確かめる、③クロスチェックする。
- クロスチェックの4つの方法：**別のAI／検索エンジン／別のメディア（書籍・専門家）／立場の異なる人**。
- Action Plan：AIの回答は「すぐコピペ」せず「まずチェック」を。
- **yohaku**：外部に出す生成物（ブログ、提案書、顧客メール）には承認前に「要確認」バッジを付け、出典リンクの有無と事実・数値の箇所を一覧で示す（design.md §9 の安全設計を補強）。

#### 23 （ノイズを）減らす（ノイズ）
- 「判断や行動につながらない」「目的と関係がない」「感情を消耗させる」情報は、すべてノイズ（炎上、専門外のニュース、他人の悪口、便利そうなだけの断片知識）。
- ノイズは注意力を奪い、感情を乱し、記憶と判断をゆがめる。
- 対処法は、①アンテナを立てる、②釣りタイトルに近づかない、③仕事と遊びの線を引く、④1日30分のデジタルデトックス。
- Action Plan：今日は30分だけスマホを手放し、情報を遮断してみよう。
- **yohaku**：通知や収集した情報を「判断・行動につながるか」でふるい分け、つながらないものは出さない。余白時間（design.md §6.4）の候補に「デジタルデトックス30分」を入れる。

### 第3章 考える

#### 29 整理させる（プロンプト設計）
- 「まとめて」「整理して」のような曖昧な指示では、出力も曖昧になる。整理には設計図が必要。
- 整理の設計図は **「目的 × 基準 × 形式 × 制約」**。
  - 目的：意思決定、資料作成、優先順位の決定、実行プラン など
  - 基準：メリット／デメリット、短期／長期、重要度／緊急度、原因／結果、リスク／リターン など
  - 形式：箇条書き、比較表、マトリクス、ピラミッド構造、ステップ構造 など
  - 制約：重複を除く、7点以内、文字数、初心者向け、実在する研究のみ など
- Action Plan：知りたいことの「目的・基準・形式・制約」を1行ずつ書いてみよう。
- **yohaku**：Codex に渡すプロンプトのテンプレートをこの4項目で組み立てる。`outputSchema` の設計にもこの軸を使える。

#### 31 書いて考える（脳のリソース解放）
- 頭の中だけで考えるのは最悪の考え方。手を動かして書く。
- 書き出すだけで、**言語化・構造化・整理・感情分離・客観視**ができ、ワーキングメモリが空く。
- Action Plan：スマホを閉じて、お気に入りのペンとノートで書いてみよう。
- **yohaku**：上司への相談メモやブログの下書きを、AIが書く前にまず本人が殴り書きできる欄を用意する（「頭の中の棚おろし」機能）。

#### 33 立体的に考える（構造化）
- 情報を **点（データ）→ 線（因果関係）→ 面（背景・文脈）→ 立体（戦略・対処法）** の順に構造化する。
- 立体的に見るためのプロンプト：「どう関係しているか？」「原因と結果に分けて」「どんな背景がある？」「時間軸で整理して」「別の立場から再評価して」。
- Action Plan：「点→線→面→立体」の順で整理してみよう。
- **yohaku**：週報や定期レポート（design.md §5）を「事実 → 因果 → 背景 → 次の行動」の4段で出力するテンプレートにする。

#### 34 問いを立てる（問い）
- 「スライドを作る」は作業の目的であって、問いではない。**「何を実現したくて、今AIを使うのか？」**を考える。
- 目的を問いに変換する例：「提出資料を完成させたい」→「相手はこの資料を読んで何を決めるのか？」「相手の不安や疑問に十分答えているか？」
- 自分で問いが浮かばなければ、「〇〇（目的）を問いに変換してください」とAIに頼む。
- Action Plan：AIに深掘りさせる前に、「何を実現したいのか？」自分自身を深掘りしよう。
- **yohaku**：タスク登録時に「このタスクの真の問い」を1行添える欄を設け、AIが目的から問いの候補を出す。

#### 35 「なぜ？」と問う（DIKWモデル）
- **データ → 情報（What/Who/Where/When）→ 知識（How）→ 知恵（Why）**。多くの人は「知識」で止まって行動できない。
- 「なぜ？」は、受け身の理解を「自分で考える」探究に変える問い。
- Action Plan：AIの答えに満足せず、「問い」を重ねて深掘りしてみよう。

#### 36 「なぜ？」をくり返す（なぜなぜ分析）
- トヨタの5 Whys。最初は**3回**から始め、届かなければ5回まで掘る。原因がわかれば対処法も決まる。
- AIに質問役をさせるプロンプト例：「〈解決したい問題〉の原因を明らかにしたいので、トヨタのなぜなぜ分析のように私に『なぜ？』をくり返してください」。
- Action Plan：今日うまくいかなかったことをひとつ選び、「なぜ？」を3回くり返そう。
- **yohaku**：夕方の振り返り（作業日記）に「なぜなぜ3回」の対話モードを用意する。AIは答えを出さず、問いを投げる役に徹する。

### 第4章 決断する

#### 50 決断して、行動する（大脳基底核）
- 決断と行動は脳内で強く結びついている。**決めたら同時に最初の行動を起こす**と、決めてから動くまでの時間が大幅に縮まる。
- 考える → 決断・行動 → 修正する。
- Action Plan：決断と同時に、ひとつ目の行動を起こしてみよう。
- **yohaku**：承認キューで「承認」したら、そのまま最初の一歩（下書きを開く、カレンダーに入れる など）につなげる。

#### 54 決断を減らす（2分ルール）
- 判断力が弱いのではなく、判断の回数が多すぎて脳が疲れている（決断疲れ）。
- **2分以内で終わるならその場でやる。2分を超えるならすぐタスクリストへ入れて忘れる**（デビッド・アレン『仕事を成し遂げる技術』の手法）。
- Action Plan：迷うのは認知コストの無駄遣い。2分で終わることは、その場で片づけよう。
- **yohaku**：メール仕分けで「2分で終わる／タスク化する」の2つに分けて提示する。2分案件は隙間時間の候補に出す。

#### 55 ルール化する（実行意図）
- **if-then ルール**（ゴルヴィッツァーの実行意図）：「XになったらYをする」と決めておけば、迷う・判断するという手順を飛ばせる。
- コツは行動を小さくすること。3分以内で終わり、成功率90%以上になるように設計する。
- 「〇〇という目標を if-then ルールにしてください」とAIに頼めば作ってくれる。
- Action Plan：「〜したら、〜する」をひとつ決めて、今日から迷わず動こう。
- **yohaku**：本人が決めた if-then ルール（例：「16時になったらブログを書く」「会議が終わったら議事録のタスクを登録する」）を登録し、トリガーで控えめに知らせる機能。Zapier のトリガーと相性がよい。

#### 56 小さく試す（成長マインドセット）
- 迷ったら本決定せず、**実験的決断**をする。条件は **低コスト・可逆的・測定可能** の3つ。
- 決断の目的を「正解を選ぶ」から「データを集める」に変える。失敗はデータになる（ドゥエックの成長マインドセット）。
- Action Plan：迷ったら「本決定」せず、まず小さく試してデータをとりにいこう。
- **yohaku**：新しいワークフローの自動化は「お試し期間」として始め、修正率や削減時間を測ってから本採用する（design.md §10 の段階導入、§11 の評価指標と一致）。

### 第5章 行動する

#### 64 行動する（行動量）
- 価値があるのは情報量ではなく**行動量**。行動するとは「0を1にする」こと。
- 知る・考える・決断する（INPUT、頭の中）→ 行動する（OUTPUT、現実）。自己満足から自己成長へ。
- Action Plan：スマホを閉じて、今日ひとつ、やりたかったことを行動にうつしてみよう。

#### 73 TO DOリストを書く（認知リソース）
- 仕事中に「次に何をしよう？」と考えるたびに集中が途切れ、5〜10分を失う。**「次に何しよう？」をなくすのがTO DOリストの最大の目的**。
- 書き方のポイントは、①スマホのアプリではなく紙に書く（誘惑を避ける）、②**15分で終わる単位**に分ける。
- AIへのプロンプト例：「この目標を15分でできるタスクに分解して」「このTO DOリストを、迷わず実行できるようにリライトして」。
- Action Plan：「15分ごとのタスク」を紙に書き、上から順に実行しよう。
- **yohaku**：朝のブリーフの優先タスクを15分単位に分けて提示する。印刷用（紙用）の1枚表示を用意する。

#### 75 オリジナリティの注入（ポストエディット）
- AIの文章は「平均値」「一般論」の集まりで、誰にも刺さらない。
- 注入する5つの方法：**①体験・経験を加える ②失敗談を書く ③自己開示する ④自分の言葉に言い換える ⑤自分の意見を書く**。目安は3割以上をオリジナルにすること。
- Action Plan：体験や意見を足して、"自分の言葉"に書き換えよう。
- **yohaku**：ブログ下書き（design.md §6.1）の公開前チェックリストにこの5項目を入れる。AIの下書きには、本人が埋める「体験」「失敗」「意見」の空欄をあえて残す。

#### 81 成長を味わう（自己効力感）
- 行動を続けられるかは自己効力感（バンデューラ）で決まる。成果よりも**成長実感**が大事。
- **「3行できた日記」**：その日できたことを3行書き、語尾を「できた」で終える。AIに「フィードバックして」「勇気づけるメッセージをください」と頼む。
- 1カ月以上記録したら、「1カ月前と比べて私が成長した点を教えて」とAIに分析させる。
- Action Plan：今日できたことを3つ書いて、AIにほめてもらおう。
- **yohaku**：夕方の作業日記に「3行できた日記」の欄を設け、AIが短く前向きなコメントを返す。月に1回、成長の振り返りレポートを出す。

### 第6章 フィードバックする

#### 85 フィードバックする（フィードバック）
- フィードバック ＝ **分析（頭の中）＋ 修正（行動・現実）**。意見をもらうだけでは不十分で、実際に修正して初めてフィードバックしたことになる。
- 自分でするフィードバック：言語化（書く）、棚おろし、振り返り、反省、記録、自己分析。
- Action Plan：アウトプットしたら、必ずフィードバックをセットにしよう。

#### 86 未来へ向けて準備する（フィードフォワード）
- 基本の型は3ステップ：**①悪かった点を3つ ②よかった点を3つ ③改善点を3つ（フィードフォワード）**。
- フィードバックは過去の分析（何が起きたか？なぜ？）、フィードフォワードは未来の行動（次はどうする？）。
- 「この振り返りをフィードフォワードに置き換えて」とAIに頼める。
- Action Plan：「悪い、よい、次はどうする？」を3つずつ振り返ろう。
- **yohaku**：週報や日記の振り返りテンプレートを「悪い3／よい3／次3」にする。「次3」はそのままタスク候補として承認キューに入れる。

#### 88 最適解を導く（Kaizen）
- AIは一発でベストを出す「回答装置」ではなく、何度でも直してくれる**「改善装置」**。
- 60点の仮の答え → プロンプトを足して70→80→90点 → 自分で実践して確かめる → 実践解。
- 最適解に近づけるための追加情報：**①目的 ②条件・背景 ③制約・リソース ④成功基準・ゴール ⑤好み・価値観**。
- Action Plan：まず出して、3回直して、ベターを積み上げよう。
- **yohaku**：下書きを「1回で完成」にせず、修正履歴を残しながら直すUIにする。ユーザーの好みや価値観をプロファイルとして保存し、毎回プロンプトに入れる。

#### 92 視座を変える（認知再評価）
- 感情は事実ではなく、解釈の結果（グロスの「出来事 → 解釈 → 感情」）。解釈を変えれば感情も変わる。
- 視座を変える4つの方法：**時間軸（過去・今・未来）／他者視点（経営者・上司・相手・専門家）／抽象度（抽象化・具体化）／立場（賛成・反対・ディベート・失敗前提）**。
- Action Plan：ひとつの出来事を、別の立場から見直そう。
- **yohaku**：上司への相談メモ（design.md §6.2）を作るときに、「上司の立場で見たら」「1年後の自分から見たら」を出力するボタン。

#### 94 反証する（シコファンシー）
- AIはユーザーに迎合しやすい（シコファンシー）。「本当ですか？」と聞き返すと、58%の確率で最初の回答を変えたという研究もある。
- 前提・根拠・論理の妥当性を確かめる。プロンプト例：「この結論が成り立つ前提条件をすべて挙げて」「根拠となる事実・データ・研究を示して」「この結論に反する研究や事例はありますか？」「前提から結論までの論理を段階ごとに説明して」。
- Action Plan：AIの答えを鵜呑みにせず、「本当に正しい？」と問い返そう。
- **yohaku**：判断が必要な提案には「反証を見る」操作を付け、別のスレッドで反対の立場から検証させる（17 のクロスチェックと組み合わせる）。

### 第7章 整える

#### 102 立つ、歩く（座位時間）
- 日本人の1日の座位時間は約7時間で、世界でも最長クラス。1時間座り続けると寿命が22分縮むといわれる。90分座り続けると前頭前野の血流が落ち、集中力や判断力が下がる。
- **30分に1回、5分立つ・歩く**。立つより歩く方がよい。ポモドーロ（25分作業＋5分休憩）で立つ、オンライン会議は立って参加する、なども有効。
- Action Plan：30分に1回、5分歩こう。
- **yohaku**：集中作業のブロックが長く続いたら、トレイから「5分歩きませんか」と控えめに知らせる。余白時間の候補に「歩く」を入れる。

#### 103 日記を書く（メタ認知）
- 日記の効果は、①思考の外部化（メタ認知が上がる）、②感情の言語化（ストレスが減る）、③個人の行動の記録（自分の材料がたまる）。
- ネットで検索できないのは「自分がどう感じ、どう判断し、どう行動したか」。**ライフログを1カ月分ためれば、AIが思考や感情のクセを指摘でき、自分向けの答えを返せるようになる**。
- 日記を書く → 蓄積する（自分専用のデータベース） → AIに分析させる → 内省 → 修正する。
- プロンプト例：「ライフログをもとに、私の認知の歪み・思考のクセを分析して」「私の強みを分析して、伸ばす方法を示して」。
- Action Plan：日記を書いて「自分データ」を蓄積しよう。
- **yohaku**：作業日記と「3行できた日記」をSQLiteにためて、月1回の自己分析レポートを作る。これが yohaku 全体の個人最適化の土台になる。

### 第8章 AI時代にあえてすべきこと

#### 113 体験する（生きた情報）
- AIは五感で体験できない。体で得た「生きた情報」は人間にしか集められず、**体験が「情報を見抜くフィルター」になる**。
- AIは過去のデータを最適化する。人間は体験によって「未来のデータ」を生み出す側に回るべき。
- Action Plan：月に1回は知らない場所に行き、体験を増やそう。
- **yohaku**：余白時間を「何もしない」だけでなく「体験」の枠としても扱う。日記に体験を記録しておくと、ブログのオリジナリティ（75）の素材になる。

## 3. yohaku への機能追加アイデア（まとめ）

### 優先度の目安

1. **すぐ効く（朝のブリーフMVPに追加しやすい）**：15分単位のタスク分解（73）、2分ルールによる仕分け（54）、「ゴール／やらないこと」入力欄（11）。
2. **夕方の振り返りとまとめて作る**：3行できた日記（81）、悪い3／よい3／次3（86）、なぜなぜ3回（36）。蓄積したデータはライフログ分析（103）の材料になる。
3. **安全設計の強化**：要確認チェックと反証の表示（17, 94）。外部に出すものを増やす前に入れる。
4. **余白・健康**：歩くリマインド（102）、体験の枠（113）、デジタルデトックス（23）。通知が多すぎてノイズにならないよう、控えめな出し方を設計する。
